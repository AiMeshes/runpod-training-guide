# RunPod 低成本训练指南

面向个人独立研究者的 RunPod 训练成本核算与落地指南。覆盖 **64M–1B 从头预训练、1B–27B midtraining、64M–27B 微调/LoRA、后训练（RLHF / RLAIF / GRPO / OPSD）**。

📄 **[完整文档 →](runpod-training-cost-guide.md)**

> 数据采集于 2026-09。RunPod 价格随供需浮动，**实际下单前务必在 console 核对**。

---

## 核心结论

**成本公式**

```
成本 = 6 × N × D / (有效FLOPS) × 单价
```

`N`=参数量，`D`=token 数。有效 FLOPS = 峰值 × MFU。**MFU 是第一杠杆，单价是第二。**

**六个最关键的判断**

| # | 结论 | 详见 |
|---|---|---|
| 1 | **1B 是 4090 的甜点上限**，3B 是成本断崖——优化器状态 12 B/param 放不进 24GB | §2 |
| 2 | **LoRA 省的是显存不是算力**。前反向 FLOPs 与全参相同，只在优化器步省 | §3.3 |
| 3 | **后训练成本在生成不在训练**。GRPO 中 70–90% GPU 时间是 rollout | §3.4 |
| 4 | **Spot 只在 spot 成本 > $200 时划算**。小模型实验全用 Secure 按需，别搞编排 | §7 |
| 5 | **不需要 GitHub Actions**。独立研究者无 CI 需求，本地 cron 或 $5 VPS 就够 | §8 |
| 6 | **别在 Mac 本地 build 镜像**。Apple Silicon 编译 amd64 的 flash-attn 会走 qemu，极慢甚至失败 | §8.3 |
| 7 | **数据永远不要从 Mac 上传**。HF 出网免费 + RunPod 入网免费，让 Pod 自己拉快 45 倍 | §9.1 |

**两个最大的钱坑**

- **volume disk 停止后涨到 $0.20/GB/月** —— 全平台最贵存储。要省钱就 `terminate` 而不是 `stop`
- **忘记 terminate 的 Pod** —— 默认花费上限 $80/hr，8×H100 忘关一晚就是 $500

## 起步路径

推荐从最短路开始，**不碰任何编排**：

1. **Secure 按需 + 官方 `runpod/pytorch` 模板**，跑通 64M 训练全流程（成本 < $1）
2. 确认训练代码本身正确后，放大到 350M–1B
3. 只有当某次实验的 spot 成本超过 $200 时，才引入 Spot + network volume + supervisor 恢复

**不要一上来就优化基础设施** —— 那是在优化一个还没跑通的东西。

---

## 立刻要做的三件事

1. **调低花费上限**：账户设置里从默认 $80/hr 降到 $5/hr 量级
2. **检查遗留 volume**：`runpodctl get volume`（遗忘的 volume disk 是持续失血点）
3. **每次实验前花 $5 校准**：跑 500 步实测 tokens/sec 再外推。文档里所有数字都是估算，实测可能差 2 倍
